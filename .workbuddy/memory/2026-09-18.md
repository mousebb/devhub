## 修复 `npm start` 报 "Electron uninstall"

- 现象：electron-vite 的 `getElectronPath` 抛 `Error: Electron uninstall`。
- 根因：`node_modules/electron` 包体在，但二进制没下载成功 —— 缺 `node_modules/electron/dist/` 与 `path.txt`（postinstall `node install.js` 当时没跑/失败）。
- 修复（10 秒，命中本地缓存 %LOCALAPPDATA%\electron\Cache）：
  ```
  $env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
  node .\node_modules\electron\install.js
  ```
- 验证：`node_modules\electron\dist\electron.exe --version` → v31.7.7；`npm start` 可正常 preview。
- 排查要点：这类报错先看 `path.txt` / `dist` 是否存在，别急着重装整个 node_modules。

## 修复「打开终端」按钮没反应

- 根因：`electron/main/system.ts` 的 `openTerminal` 用 `spawn(exe, [], { detached: true })`。
  Windows 下 Node 的 detached 会带 DETACHED_PROCESS，子进程拿不到控制台 → cmd.exe 起不来窗口直接退出。
  对比 `openVSCode` 走 `cmd /c start` 所以正常，只有终端按钮失效 —— 与现象完全吻合。
- 修复：改成 `spawn('cmd.exe', ['/c','start','', exe, '/k' | '-NoExit'], { cwd, windowsHide: true, stdio:'ignore' })`，
  加 existsSync(dir) 校验 + child 'error' 捕获 + 400ms 成功窗口，返回 `{ok,message}`。
- UI：`ProjectCard.tsx` / `ProjectDetail.tsx` 的 `openExternal` 不再丢弃返回值，失败时 `toast('error', msg)`。
- 验证：tsc --noEmit 通过，electron-vite build 通过（out/ 已更新）。
- 通用教训（Electron + Windows）：凡是要弹出可见控制台窗口的，都别用 detached，走 `cmd /c start`。

## 修复 DevHub 重启后历史日志消失

- 现象：关掉 DevHub 再打开，日志面板就空了，只能去 %APPDATA%\DevHub\logs 翻文件。
- 根因：`LogStore` 用「内存 buffer + 磁盘 .log 追加」双写，但只读内存 buffer；`loadLogs`（前端）已有合并去重逻辑，后端 `getLogs` → `logStore.get()` 只返回内存，**磁盘从不被读回**。DevHub 重启内存清空 → 历史丢失。
- 修复：
  - `log-store.ts` 新增 `getOrLoad()`（async）+ `loadFromDisk()`：内存为空时读磁盘最近 maxLines 行（去掉写入时的行首时间戳，ts 倒推避免挤在同一时刻），顺便对超长文件截断回写控制体积；新增 `loadedFromDisk` 标记避免重复 IO；`clear()` 也清掉该标记。
  - `index.ts` 的 `CHANNELS.logsGet` handler 改为 `await logStore.getOrLoad(...)`。
  - 前端 `loadLogs` 合并逻辑原样复用，无需改。
- 验证：tsc + electron-vite build 通过。
- 已知取舍：读回的历史日志 stream 统一按普通输出（不区分 stderr / 系统行配色），时间戳为倒推近似（精确到内容可见即可）。settings.defaultTerminalMode 本就是 'devhub'，现有两个服务也都是 devhub，无需改动。

## 修复 DevHub 重启后"孤儿进程"显示为未运行

- 现象：devhub 里启动的项目，关掉 DevHub 再开，UI 显示未运行，但进程实际还在跑（关不掉）。
- 根因：`ProcessManager.processes` 是纯内存 Map。DevHub 退出后该表丢失；Windows 下 devhub 模式 `spawn(shell:true)` 起的进程树（cmd→npm→node）不随 Electron 退出自动死，成了孤儿进程。重启后 `snapshot()` 返回空 → UI 全显示 stopped。
- 方案（用户选的方案 1：显示为运行中且可关闭）：新增"运行记录"落盘。
  - `process-manager.ts`：新增私有 `runtime.json`（路径由 index.ts 传 `join(dirname(configManager.configPath),'runtime.json')`）；
    `persistRunRegistry()` 在每次 `emitStatus` 后把 running/starting 且带 pid 的服务 `{pid,terminalMode,startedAt,command,cwd}` 写盘（原子 tmp+rename）；
    `recoverOrphans()` 启动时读回，过滤 `isAlive(pid)` 存活项，重新登记为 `status:'running'` 并打 `recovered:true`（无实时日志但可停止），已死 PID 自洁清掉。
  - `index.ts`：`whenReady` 里 `processManager.recoverOrphans()` 须在 `createWindow()` 之前调用，保证首次 `getRuntimeSnapshot()` 能拿到。
  - `types.ts`：`ServiceRuntime` 加 `recovered?: boolean`。
  - UI：`ProjectDetail.tsx` 服务卡加「已恢复」Badge + 提示"实时日志不可用"；`ProjectCard.tsx` 运行行加「已恢复」标记。
- 验证：tsc --noEmit 通过，electron-vite build 通过（out/ 已更新）。
- 已知取舍：恢复的服务只能停止、看不到实时日志（进程树已不归本进程）；停止走 `taskkill /PID /T /F` 杀整棵树，对 devhub 模式有效。外部终端模式（wt.exe）的 taskkill /T 不一定杀得掉其孙进程，属既有局限，用户当前全 devhub 模式不受影响。

## 修复 DevHub 跑 dev 服务被误判为生产环境

- 现象：某 Nest 服务 `npm run start:dev` 在 DevHub 里启动即 `[配置安全校验] 生产环境发现不安全配置，已拒绝启动`；同一条命令在 cmd 里正常。
- 根因：`ProcessManager.spawnInternal/spawnExternal` 用 `{ ...process.env }` 把 **DevHub 自身的运行环境** 整个复制给子进程。DevHub 是打包后的 Electron 应用，`process.env.NODE_ENV === 'production'`（这是 DevHub 自己的构建模式），被 Nest 服务继承后误判为生产环境触发校验。cmd 里 NODE_ENV 为空/development 所以正常。
- 修复：新增 `buildServiceEnv(service)`，复制 env 后 `delete env.NODE_ENV`，再应用 `service.env` 覆盖（用户可在 DevHub 的 service.env 里显式设回 NODE_ENV 以跑真生产）。两处 spawn 统一改用此法。
- 验证：tsc --noEmit 通过，electron-vite build 通过（out/ 已更新）。

## 本轮四项：设置弹窗 / 设置不生效 / 数据目录搬出 C 盘 / 侧栏分组树

1. **点「设置」弹出「Help / Windows 终端 1.24.11911.0」信息框**
   - 根因：`system.ts getTools()` 的工具表里有 `{ name: 'wt', arg: '--version' }`，设置页 mount 时调 `getTools()` → `where wt.exe` 命中后**执行** `wt --version`。Windows Terminal 不支持该参数，收到非法命令行会直接弹一个标题为 `Help` 的系统 MessageBox（内容就是它的版本号）。
   - 修复：工具表项改 `{ name: 'wt', exe: 'wt.exe' }`（`arg` 缺省 = 只 `where` 定位、不执行）。其它工具不受影响。
2. **「关闭窗口最小化到托盘」开关点不动**
   - 根因：`main/index.ts` 的 `config:save` handler 收下入参 `config` 却只用它读 maxLogLines，然后 `saveAndBroadcast()` → `configManager.save()`（无参）→ 存的是**主进程里那份没变的 config**。等于设置页所有改动都被丢弃（开关回弹、theme 等同样失效）。
   - 修复：handler 改为只把入参的 `settings` 合并进主进程 config：`configManager.update(c => { c.settings = { ...c.settings, ...settings } })`。**故意不接收入参里的 projects**，否则渲染进程的陈旧快照会覆盖主进程维护的 lastStartedAt / 分组状态。
3. **配置 / 日志目录搬到 DevHub 自身目录（不在 C 盘用户目录）**
   - `config-manager.ts` 新增导出 `resolveDataDir()`：`DEVHUB_DATA_DIR` env > 打包时 `dirname(app.getPath('exe'))` > 开发时 `process.cwd()`，再拼 `data`。→ `data/config.json` + `data/logs/`（`runtime.json` 跟着 configPath 目录走）。
   - 旧数据一次性迁移 `migrateLegacyConfig()`（从 `%APPDATA%\devhub` 拷 config.json + logs）。**坑**：`ensureDirs()` 若先跑，logs 目录已存在会让 `cpSync` 被跳过 → 迁移必须放在 ensureDirs 之前。

   - `AppInfo` 加 `dataDir`；设置页多显示一行「数据目录」+ 一个「数据目录」按钮，文案同步更新。`.gitignore` 加 `data/`。

## 界面中英双语（设置里切换）

## 设置页三个开关挤在一行（已修）

- **根因**：`ui.tsx` 的 `Toggle` 根元素是 `<button className="inline-flex ...">` —— **行内级**。在 `ProjectEditor` 里它父级是 flex 容器（flex 子元素会被块化）所以正常；但设置页「通用」区块的三个 Toggle 是 `space-y-3` 区块的直接子元素，三个 inline-level 按钮于是排在同一行文本上，`space-y` 的 margin 只做行内微调、不换行。
- **修法**：`inline-flex` → `flex w-fit`（块级 + 宽度贴合内容，避免点击热区被拉满整行），并给开关滑块补 `shrink-0`。一处改动即让 `space-y-3` 恢复生效（12px 间隔，与同区块其它行一致）。两处调用点（ProjectEditor 的 `flex items-center gap-4` 与 `flex flex-col justify-end gap-1.5`）视觉不变。
- 教训：Tailwind 里给"可复用的表单行组件"用 `inline-flex` 是坑 —— 同一组件在 flex 容器里看不出问题，落到块级流里就整行并排。组件根元素默认用块级 `flex w-fit` 更稳。
